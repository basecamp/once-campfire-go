# Engine implementation plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Tasks marked **[detailed]** are executable as written; tasks marked **[scoped]** are expanded into detailed steps when their milestone starts, with the files/approach/exit recorded here.

**Goal:** Add a from-scratch performance engine to the once-campfire-go fork that beats the Rust port's medians on every official-harness HTTP row and cable, with all parity validations green.

**Architecture:** Strangler engine at the `front.Serve` seam (`plans/2026-10-05-engine-design.md`): compiled route ownership, cached gzip members assembled per request, thin CGO SQLite reads, compiled renderers, version-keyed in-process caches; legacy `web.Server` remains the fallback and differential oracle.

**Tech Stack:** Go 1.27.1 (mise), cgo, mattn/go-sqlite3 (CGO), existing `internal/*` packages, `github.com/sebishogun/simd{,http,json}` as measured candidates, Python bench harness `bench/application`, official `../once-campfire-elixir/bench`.

**Rule for every task:** every build/test command carries an explicit timeout; no build/test on a repeat loop; gates run bare or under `set -o pipefail`; measurements follow the design §6 contract (interleaved, minimum, quiet machine, load < 1); a measurement that argues against a change is recorded in `plans/wrong.md`.

**Encoding contract (from the ENGINE-10 quality review, must be satisfied by this wiring):** in `main.go`, ENGINE-11 wraps the legacy handler in `front.Deflate` (so fallback routes keep gzip) and passes the engine root with `SkipDeflate: true`. Engine-owned responses must set `Content-Encoding` **and** `Vary: Accept-Encoding` on every cacheable response — the front cache keys its variants on `Vary` and clones headers before the public chain adds it. The engine also owns the 406 negotiation policy and the `No-Gzip-Compression` / `DisableGzipOnAuth` policy for responses it pre-encodes (PublicCompression applies those vetoes only to bodies it compresses itself and cannot strip an app-set `Content-Encoding`). Add a differential assertion that legacy-fallback responses through the engine root are still gzipped.

### ENGINE-12: piececache [detailed]

**Files:** Create `internal/piececache/cache.go`, `internal/piececache/cache_test.go`, `internal/piececache/assemble.go`, `internal/piececache/assemble_test.go`, `internal/piececache/bench_test.go`.

**Step 1: Failing tests first.**
- Entry stores `raw []byte`, gzip `member []byte`, `digest [32]byte` (SHA-256 of raw), byte-cost accounting; `Get` returns immutable views (immutability by convention). No `crc32` field: multi-member gzip needs no CRC combining (design §3.4), so the sketch's field was dropped.
- Poisoning test: put an entry, mutate the source buffers passed in, assert the cached bytes equal the originals (defensive copy contract).
- LRU byte-budget test: entries evicted oldest-first, oversized entries rejected, replace-same-key atomic.
- Assembly test: multi-member gzip with `compress/gzip` reads back the exact raw concatenation; identity assembly concatenates raw; ETag input = ordered piece digests.
- `-benchmem`: `Get`+`Assemble` for a 3-piece / ~80 KB page reports `0 allocs/op` given caller buffers.

**Step 2: Run to fail** — `timeout 120 go test -timeout 100s -benchmem ./internal/piececache -v -bench .`.

**Step 3: Implement** — map+`container/list` (existing fragment-cache shape), mutex, byte budget default 32 MiB (env-overridable, same key as the fragment cache), `Assemble(dst []byte, pieces []*Entry, encoding) ([]byte, etag)`; caller supplies `dst` (arena discipline); no `sync.Pool`.

**Step 4: Pass + bench numbers recorded** in the task commit message (min of 6).

**Step 5: Commit** — `git add internal/piececache && git commit -m "piececache: content-versioned compressed pieces with zero-alloc assembly"`.

## Evidence discipline

- Every task's commit message carries the command and the observed numbers (min and median) when performance is claimed.
- Published numbers only from quiet runs (load < 1), interleaved orders, explicit timeouts; raw artifacts under `bench/results/` (repo convention) or ignored `tmp/`.
- `plans/wrong.md` is created on the first rejected change.

## When stuck (mandatory sequence)

A stalled optimization never gets a speculative rewrite. The order is:

1. **Profile the real workload**: 10 s CPU pprof and an allocation profile against the actual seed and loadgen, at the target concurrency (`bench/profile` or `GO_CPU_PROFILE`); name the top flat and cumulative entries.
2. **Attribute with counters**: `perf stat -e instructions:u,cycles:u` on the specific route, interleaved with the previous build, when the wall-clock delta is below the harness spread.
3. **Read the assembly**: `go test -c -o /tmp/x.test ./internal/<pkg> && go tool objdump -s '<pkg>\.<fn>' /tmp/x.test` (or objdump the built binary) for the hot function; look for spills, bounds checks, missed inlining, call overhead in loops.
4. Only then write the variant; re-measure interleaved, minimum of repeated samples.
5. Record the finding in the task or `plans/wrong.md` whether or not it worked; a negative result with a number is a deliverable.

Apply the tenets in the fix, in order: layout/data first (pieces, arenas, SoA where it applies), then zero allocations on the path, then bulk/SIMD kernels with verified dispatch, then pruning, then parallelism — and only then pooling, with a poisoning test.

## Optimization queue after ENGINE-18 (from profile-20261006 + official checkpoint)

Ordered by measured CPU share / gap; one implementer at a time, reviews between.

- **ENGINE-19 — message-page cache by room version** (room 19.5% + messages 19.7% are the same reference scan): cache page references keyed by a room message-version (in-process registry bumped by writes, seedable from the DB); derive the messages-page ETag from the cached piece digest instead of rebuilding `messageFreshness` (messages 8.1%).
- **ENGINE-20 — sidebar version-keyed fragment cache**: serve sidebar hits without re-reading all room/member rows (cheap version source + registry), one JOIN via fastdb for `SidebarRooms`/`RoomMembers`/`DirectPlaceholders`, skip pageSetup on hits. Biggest ratio gap (1.76× official).
- **ENGINE-30 — search**: fastdb FTS positional read + bounded `(query, corpusVersion)` result-piece cache with poisoning/fuzz coverage. FTS scan is 28.1% of search CPU.
- **ENGINE-31 — post write lane**: writer queue with group commit (batch pending message writes into one transaction), WAL checkpointing off the writer (Rust PR43 shape), same WAL/NORMAL durability; fastdb reads inside `messageViews`; webhook dial/DNS reuse. Commit serialization 14.2% + `messageViews` 40.2% cum.
- **ENGINE-32 — compiled message fragment renderer** (`fastrender`): byte-golden against `html/template` `message-uncached`, zero-alloc into caller buffers, share the rendered fragment between the Turbo response and the cable broadcast (Rust pattern). Kills `reflect.Value.call` 12.9% and helps every cache miss.
- **ENGINE-40 — cable**: measure first (`bench/application --cable-clients`, 100/1000/10000, deflate on/off) against Rust; then the Rust-shaped fixes: header-first reader without per-idle-socket buffer memset, batched/vectored writes, authorization batching. Entirely unmeasured so far.
- **ENGINE-41 — transport (measured-gated)**: socket write is 23.1% room / 20.7% messages. If still dominant after ENGINE-19..32, evaluate vectored writes / owned output loop with `simdhttp` parse (5x head-parse measured); adopt only with interleaved evidence.
- **ENGINE-42 — auth + misc allocations (measured-gated)**: version-keyed session cache (risky, poisoning tests first), net/http request allocations, shared `httpcompat.Encoding` evaluation, rest of the re-review residuals.

## Adopted from once-campfire-elixir PR #5 (lau; Elixir beats Rust on sidebar/search there)

Their measured result (Docker Desktop, Elixir improved vs Rust ccece30):
sidebar 32,121 vs 27,538; search 26,790 vs 25,488 — via table-generation
caches, not compiler tricks. Transferred design work:

- **ENGINE-43 — table-generation read cache** (their single biggest win; CPU
  per request fell ~5x on sidebar/search): cache read results keyed by the
  generation of the tables they touch; every in-process write bumps its
  tables' generations after commit; detect *external* commits with SQLite's
  WAL transaction counter (read the `-shm` WAL-index header) checked once per
  request. Subsumes/supersedes the narrow version keys of ENGINE-19/20/30 and
  extends to session+user (joined), membership/bans, account, attachments,
  invitation count, recent searches, return room. Cache correctness tests
  must enumerate every write helper.
- **ENGINE-44 — finished-response caching + pipeline trims**: cache the
  completed messages/search responses (no assembly on hit; no per-request
  dynamic value there), room shell keyed by input digest, gzip kept by body
  digest; `Accept-Encoding` decision cached per header value; `.json`/`.xml`
  suffix test instead of regex; security headers appended in one pass;
  PublicFiles fast path for paths that cannot name a public file; whole-body
  deflate keyed by SHA-256 shared with the ETag.
- **ENGINE-45 — post query-count reduction**: audit `createMessage`'s SQL
  statements (their post went 31 → 16): render the new fragment from
  data the request already holds (creator, room, body, empty boosts); skip
  the embed SELECT for a fresh body without embeds (AUTOINCREMENT ids are
  never reused); read push involvement in the subscription join instead of
  per subscription; route repeated bans/attachment checks through the read
  cache.
- **ENGINE-46 — compiled route matching**: their route recognition compiled
  to pattern clauses instead of running regexes per request; ours runs a
  177-entry regex contract scan plus a mux regex linear scan. Compile to a
  segment-trie/wildcard matcher (`simdhttp` router is the measured
  candidate) while preserving the contract table semantics exactly.

Also note (non-transferable): they removed Thruster and CSRF tokens
(Sec-Fetch-Site, as Rust), dropped SQLite mmap (readers remap after each
commit), and moved Redis fan-out in-process — our port already has the
in-process equivalents or never had them.

## Go-specific levers (user-mandated additions)

- **ENGINE-47 — GC policy and memory limit**: measure GC share (profiles show
  9–12% on read routes); tune `GOGC`/`GOMEMLIMIT` (or
  `debug.SetGCPercent`/`SetMemoryLimit` from env) toward <1% GC on read routes
  without regressing peak memory beyond the acceptance bound. Expose in README
  and container env defaults; measure with the official harness's memory rows.
- **ENGINE-48 — per-request arena**: response buffer + parts + header scratch
  from a per-connection arena reset per request (merge with the existing
  pooled assembly buffer), removing the remaining per-request allocations;
  poisoning tests first; `-benchmem` proof.
- **ENGINE-49 — precomputed response framing**: cache the status line + header
  block per route/encoding variant; `Date` cached per second; avoid
  `http.Header` map writes on the hot path (write bytes where the engine/front
  owns the writer).
- **ENGINE-50 — cache-fill compression level**: compress cached members at
  gzip level 9 (one-time cost; per-request bytes reduced) and emit zstd when
  the client accepts it (`Vary: Accept-Encoding` variants preserved); measure
  compressed size and official throughput; revert if the socket-write saving
  does not show up interleaved.
